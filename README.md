**macOS 菜单栏语音输入 · 专为中英混说优化 · 100% 本地运行**

macOS 菜单栏语音输入。按住一个键说话，松开后文字直接落在当前光标处 —— 任何 App 的任何输入框都行。

跟同类工具的区别在于**专门为中英混说做了优化**。说"这个 pipeline 的 latency 有点高"这种话时，现有工具基本都只做到"能认"，标点、空格、术语大小写全是乱的。

```
Qwen3-ASR 原始输出   嗯,这个pipeline的latency有点高,我们要不要换个schema?
MixDictate 输出      这个 pipeline 的 latency 有点高，我们要不要换个 schema？
```

100% 本地运行，音频不出这台电脑。

## 安装

> 完全没用过终端也能装完。下面每一步都写清楚了要做什么、看到什么算成功。
> 卡住的话直接跳到最后的[「装不上怎么办」](#装不上怎么办)。

### 你需要什么

| | 要求 | 怎么确认 |
|---|---|---|
| 电脑 | Apple Silicon Mac（M1/M2/M3/M4） | 左上角  › 关于本机，「芯片」那行写着 Apple M… |
| 系统 | macOS 13 或更新 | 同上，「macOS」那行 |
| 硬盘 | 约 3 GB | 模型 1.2 GB + Python 依赖 |

**Intel Mac 跑不了。** 这个模型靠 Metal 加速，那是 Apple 芯片独有的。

### 第 1 步：打开终端

按 `⌘ + 空格`，输入 `终端`，回车。会出来一个黑底或白底的窗口，能打字就对了。

### 第 2 步：把项目下载下来

把下面这行**整行复制**，粘进终端，回车：

```bash
git clone https://github.com/aubreyzhou1208/MixDictate.git ~/MixDictate && cd ~/MixDictate
```

第一次用 `git` 的话，macOS 会弹窗问你装不装「命令行开发者工具」—— 点**安装**，
等它装完（几分钟），然后**把上面那行再跑一次**。

> 想装到别的地方就把 `~/MixDictate` 换成你想要的路径。以后所有维护命令都要
> 在这个目录里跑，忘了在哪儿就跑 `./scripts/doctor.sh`，第一行会告诉你。

### 第 3 步：装

```bash
./install.sh
```

它会依次做这些事，每一步都会打印出来：

1. 检查你的机器符不符合要求
2. 建一个独立的 Python 环境（不会动你系统里的 Python）
3. 装转写要用的依赖
4. 编译 App
5. 装进「应用程序」文件夹并启动
6. 复查一遍，打印一串 ✅

**第一次要几分钟**，主要花在下载依赖上。中途缺 Xcode 命令行工具的话它会替你
弹出安装窗口，装完再跑一次 `./install.sh`。

### 第 4 步：给两个权限

菜单栏右上角会出现一个麦克风图标。第一次要给两个权限：

**麦克风** —— 会自动弹窗，点「允许」。

**辅助功能** —— 要手动加，macOS 不给这个权限的弹窗：

1. 打开「系统设置」 › 「隐私与安全性」 › 「辅助功能」
2. 点左下角 `+`
3. 选「应用程序」里的 **MixDictate**
4. 把开关打开

> 没有辅助功能权限的话，**按快捷键会完全没反应** —— 全局按键监听本身就需要
> 它，不只是「插入文字」需要。

### 第 5 步：等模型下载完

菜单栏图标是**沙漏**时说明还在启动，第一次要从 Hugging Face 拉 1.2 GB 的模型。
变成**麦克风**图标就能用了。

### 第 6 步：说一句话

在任何输入框里（备忘录、浏览器、终端都行）：

**按住右 Option 键说话，松开。** 文字会出现在光标处。

按 `Esc` 可以中途取消。

**开机自启**：

### 开机自启

```bash
./scripts/autostart.sh install     # 装
./scripts/autostart.sh status      # 查
./scripts/autostart.sh uninstall   # 卸
```

### 每次改动后复查

```bash
./scripts/verify.sh
```

它逐条查那些**已经犯过的错**有没有重新出现：权限是不是真的有效、采集是不是
全零、回声消除有没有被打开、签名身份是不是固定的、服务和模型在不在。
每一条都对应 `CLAUDE.md` 里记着的一个具体教训。

`install.sh` 装完会自己跑一遍，自动更新装完也会跑，有回归弹通知。
**这是刻意做成自动的** —— 之前真正失败的那一环从来不是"不知道要查什么"，
而是"记得去查"。

### 自动更新

下面这些命令都要**在仓库目录里**跑（就是有 `install.sh` 的那个目录）。
忘了克隆到哪儿了的话，`./scripts/doctor.sh` 和 `autoupdate.sh status`
都会把完整路径打出来。

不想每次都手动 `git pull && ./install.sh` 的话：

```bash
./scripts/autoupdate.sh install    # 每分钟检查一次，有新版本就自动装
./scripts/autoupdate.sh status     # 看状态和最近的更新记录
./scripts/autoupdate.sh run        # 立刻检查一次
./scripts/autoupdate.sh now        # 立刻更新，不管是不是刚用过
./scripts/autoupdate.sh uninstall  # 关掉
```

更新完会弹一条通知告诉你装到哪个版本了。想确认机器上跑的到底是哪一版，
`./scripts/doctor.sh` 顶上的「版本」一栏会直接告诉你本地、远端、以及
**已安装 App 的编译时间** —— 拉下来了不等于装上了，这三个数字要分开看。

**为什么是轮询而不是推送**：真正的推送要求这台 Mac 能被外部连接（公网地址
或内网穿透），代价太大。所以改成把检查做得极便宜 —— 每次只跑一句
`git ls-remote`，一次 HTTPS 往返、不下载任何对象、几十毫秒。这样每分钟查
一次的开销可以忽略，效果上就接近推完立刻装。没有更新时不写日志，
免得每分钟一行把真正有用的记录淹掉。

几条保护，都是为了不在你正用着的时候把 App 拆了：

- **工作区有未提交的改动就跳过** —— 绝不覆盖你自己的修改
- **只做快进合并** —— 有分叉说明本地有额外提交，那种情况需要人来判断
- **三分钟内用过听写就跳过这轮** —— 等下一轮再更。但这条单独看是对的、
  组合起来会出事：你一边测一边等新版本，每分钟都在三分钟内用过，更新就
  永远排不上队，表现成「明明改了，装到机器上却一直是旧的」。所以推迟有
  上限，**同一个版本最多等 10 分钟就照装**；等不及就 `autoupdate.sh now`
- **编译失败时旧版本原封不动** —— `install.sh` 先编译成功才动 `/Applications`

## 用法

**按住右 Option 说话，松开。** 文字出现在光标处。

说话时屏幕下方会有浮层。**两种模式用两种形态**，因为它们要解决的问题不同：

| 模式 | 形态 | 为什么 |
|---|---|---|
| 普通 | 完整文字浮层 | 文字要松手才出现，这段时间里浮层是唯一的反馈 |
| 边说边写 | 小指示器（● 正在听写，圆点会呼吸） | 文字已经在光标处了，再显示一遍是噪音；但完全不显示又会让人不确定它在不在工作 |

小指示器**不受 `showLiveOverlay` 控制** —— 实时写入模式下它是唯一的进行中
反馈，被那个开关关掉就等于没有反馈。`showLiveOverlay` 管的是显示全文的大浮层。

圆点做呼吸效果是有意的：静态的点看不出程序有没有卡住，会动的点一眼就知道
它还活着。

浮层不会抢焦点，所以你正在打字的那个输入框始终保持活跃。
两种都不想要的话，把 `showLiveOverlay` 关掉。

### 边说边写进输入框

**开启方式**（菜单栏图标找不到时用命令行，见下）：

```bash
./scripts/config.sh set liveInsertion true
```

或者设置里打开「边说边写进输入框」，文字就直接出现在光标处，不经过浮层、
也不用等松手 —— 少掉最后那次粘贴，感觉快很多。

实现上不是一味往后追加：中间结果会被模型改写（说到后面它会回头修正
前面听错的词），所以每次都跟上一次写进去的内容比对，公共前缀留着不动，
只把不同的尾巴退删掉重打。改动量最小，看起来就是文字自己在修正。

**两个代价**，所以默认关闭：

- 你会看到文字被退删重写，有些人觉得晃眼
- **听写过程中别自己动光标或改字** —— 那之后程序对"已写入内容"的记忆
  就错了，退删会误伤你的内容。单次退删有 200 字上限兜底，但最好别试

## 热词表

菜单里点「编辑热词表…」，或直接编辑
`~/Library/Application Support/MixDictate/hotwords.txt`。
**保存即生效，不用重启。**

```
Kubernetes            # 普通热词：解码时偏置 + 输出时统一大小写
Supabase

k8s => Kubernetes     # 别名：听错的写法强制改回来
拍森 => Python
```

这是提升准确率**性价比最高**的一环。把你常说的人名、项目名、技术术语加进去，
效果比换更大的模型还明显。

两层机制互补：`context` 偏置是软的（让模型更容易听出这些词），别名替换是硬的
（模型仍然听错时按规则改回来）。

### 文字怎么送进输入框

单一机制做不到"任何地方都能输入"，所以按顺序降级：

| 顺序 | 机制 | 覆盖面 | 盲区 |
|---|---|---|---|
| 1 | 安全输入模式开着时 → 辅助功能接口直写 | 不受合成按键限制 | 终端、部分 Electron 的文本视图不支持 |
| 2 | 剪贴板 + 合成 Cmd+V（默认） | 绝大多数 App，含终端 | 安全输入模式；个别拦截粘贴的 App |
| 3 | 合成 Unicode 按键逐字输入（可选） | 拦截粘贴的 App | 安全输入模式；长文本较慢 |

**安全输入模式**是 macOS 的一个全局开关，密码框和某些终端配置会打开它。
开着的时候系统会拦截**一切**合成按键 —— 不报错、不提示，纯粹是没反应。
这时唯一的路是辅助功能接口；那条也走不通的话，文字会留在剪贴板里，
浮层会提示你按 Cmd+V。

顺带说明：Terminal.app 默认**不**开安全输入，iTerm2 的
"Secure Keyboard Entry" 也默认关闭，所以终端里正常能用。

拆成两个进程是因为模型在 Python/MLX 里，而全局快捷键和文字注入必须用原生
macOS API。HTTP 只走 127.0.0.1。

**MLX 的线程亲和性**：GPU stream 是线程局部的，在 A 线程加载模型、到 B 线程
推理会直接抛 `There is no Stream(gpu, 1) in current thread.`。所以模型加载和
每次推理都固定在同一个专用线程上（`max_workers=1` 的执行器），既不阻塞事件
循环，也满足亲和性。用 `asyncio.to_thread` 会踩中这个坑，而且症状极具迷惑性 ——
命令行直接调模型正常，HTTP 服务每次 500。`test_thread_affinity.py` 锁住了这条。

App 启动时先探一次 `/health`：已经有服务在跑就直接接管，否则自己拉起一个，
退出时只关自己启的那个。

**实时结果**不是流式解码 —— Qwen3-ASR 是整段推理的模型，没有流式接口。

最初的做法是每次刷新都重转"从开头到现在"的整段音频。这在短句上没问题，
但开销随时长**平方级**恶化：说 30 秒时每次刷新要转 30 秒，松手后再转一遍
30 秒。用户的原话是"超过三十秒就非常慢，整理的时候更慢"。

现在改成**按静音切段**：

```
说话 ──停顿── 说话 ──停顿── 说话 ──（松手）
└─ 段1 ─┘    └─ 段2 ─┘    └─ 尾巴 ─┘
 转一次        转一次        转一次
 就定稿        就定稿      松手时转
```

- 检测到 **1 秒**以上的停顿，且当前段至少 1.5 秒，就在那里切一刀
- 一直不停顿的话，段落到 **8 秒**也强制切 —— 否则延迟会无上限地涨
- 切完的段落转写一次就**定稿**，之后再也不碰
- 每次刷新只转"最后一段"，开销跟总时长无关 —— 说 5 秒和说 3 分钟一样快
- 松手时也只转最后那一段，前面的直接拼上

优先切在停顿处是为了不把一个词劈成两半；8 秒那条是兜底，可能切在词中间，
但比让延迟无上限地涨强。

停顿阈值一开始是 0.6 秒，太敏感 —— 说话时想下一句怎么讲，很容易停顿半秒多，
那不是句子结束。切在那里模型会补一个句号，句子就被硬生生断开。现在提到 1 秒。

### 分段的代价，以及怎么补回来

分段解决了速度，但有实实在在的代价：**每段只看得到自己那两三秒**。

- **识别变差** —— 整段推理时模型能用前后文纠正听错的词，分段之后不能
- **标点靠猜** —— 模型看不到后面还有话，只能按"这段说完了"来标点

试过用停顿时长判断句子有没有说完（停 2 秒以上就保留句号），**那个思路是错的**：
想词时停三秒和说完一句停三秒，从音频上分不出来。

现在的做法是**把两件事分开**：

| | 用途 | 怎么做 |
|---|---|---|
| 说话过程中 | 实时预览 | 分段，只转最新一段，快 |
| 松手之后 | 最终结果 | **拿完整音频重转一遍**，模型看得到全文 |

段落拼接时**一律去掉句末标点** —— 少一个该有的句号，你补一下就行；
多一个不该有的句号，是把你的一句话劈成了两句。真正的标点由完整音频那一遍给出。

超过 `fullPassMaxSeconds`（默认 45 秒）的录音不重转，那笔开销正是当初做分段
要解决的问题。想改：

```bash
./scripts/config.sh set fullPassMaxSeconds 90   # 更看重准确率
./scripts/config.sh set fullPassMaxSeconds 0    # 完全关掉，最快
```

### 第一次听写为什么会慢

MLX 的 Metal 计算核是**首次推理时才编译**的。只加载模型权重不够 ——
那笔编译开销会落在你的第一句话上，第二句就正常了。

所以预热要**真的跑一次推理**（用一段 0.6 秒的极轻正弦波，不能用纯静音：
解码器可能走短路，那样就白热了）。两个时机：

- 服务启动时热一次
- **按下说话键时**再检查一次，超过 2 分钟没推理就补热 —— 按下到第一次
  转写请求之间约有 0.8 秒，足够热完，比在后台一直空转烧电划算

### 对识别结果的加工，按误伤风险分级

这个项目的一条原则：**删错的代价比留着噪音大得多** —— 多余的内容你一眼
就能看出来并删掉，但被删掉的内容你根本不知道它曾经存在过。所以每一项加工
都按误伤风险决定默认值，而且都能单独关掉：

| 功能 | 默认 | 误伤风险 |
|---|---|---|
| 去「嗯」「呃」 | 开 | 几乎没有，只删句首和停顿后的独立语气词 |
| 中文标点转全角 | 开 | 不改内容，只改标点形态 |
| 口语符号转符号 | 开 | 只在紧邻 ASCII 字母数字时转，中文语境不动 |
| 口语数字转数字 | 开 | 规则保守：单字不动、成语白名单、时间不当小数 |
| 合并卡壳重复 | **关** | 高，见下 |

```bash
./scripts/config.sh set spokenNumbers false   # 觉得哪项在乱改就关掉它
```

### 为什么「合并卡壳时的重复」默认关闭

口述卡壳时确实会把前半句重说一遍（「我觉得我觉得这个方案」），代码和测试
都在，但**默认不启用**：

- 「超级超级好」是刻意的口语强调，不是卡壳
- 「谢谢」和「谢谢谢谢」该收成什么，没有可靠判据

删错的代价比留着重复大得多 —— 多余的重复你一眼就能看出来并删掉，
但被删掉的内容你根本不知道它曾经存在过。要开的话：

```bash
./scripts/config.sh set collapseRepeats true
```

### 为什么做不到云端那种「几乎无延迟」

云端流式识别用的是**真流式模型**：音频一帧帧喂进去，解码器增量吐字，
从不回头重算。Qwen3-ASR 是整段推理的模型，**没有流式接口** —— 我们只能靠
"切段 + 每段转一次"去逼近。段落越短延迟越低，但太短模型缺上下文、准确率
会掉，所以下限卡在 1.5 秒。

这是模型本身的限制，不是实现问题。真要更低的延迟，得换成支持流式解码的
模型（比如 NVIDIA Parakeet 系列），代价是中文准确率大幅下降。

两个还在的优化：刷新间隔按**未定稿段落**的长度算（不是总时长），
`min(1.5, max(0.8, 段落时长 × 0.3))`；松手时如果尾巴比最后一次中间结果
几乎没长（0.4 秒以内），直接复用那次的文字，跳过整整一次推理。

另外中间结果不做「去掉热词重试」—— 那会让单次耗时翻倍，而实时反馈最怕慢。

另外：模型推理串行加锁；同时最多只有一个中间请求在飞；中间结果不写转写记录。

### 后处理为什么这么写

中英混说有几个规则不能想当然：

- **标点按整句语言判定，不是紧邻字符。** 中文句子经常以英文词结尾（"换个 schema?"），
  按紧邻字符判断会漏掉这些，而它们恰恰最需要转全角。
- **两侧紧贴 ASCII 字母数字时不转。** 保住 `3:30`、`a,b` 这类。
- **句点规则更严**（前面不是数字、后面是空格或结尾），保住 `3.14` 和 `config.json`。
- **叠词白名单。** "就是就是"是卡壳要压缩，"谢谢""看看"是正常中文不能动。

每条都有对应的测试锁着，见 `server/tests/test_postprocess.py`。

## 边放视频边听写

**先说结论：靠人声门限，不要开回声消除。**

```bash
./scripts/config.sh set echoCancellation false   # 默认就是关的
./scripts/config.sh set voiceThreshold 0.05      # 挡外放靠这个
```

### 为什么不用回声消除

macOS 自带的语音处理单元确实能做回声消除 —— 它知道系统正在往扬声器送什么，
就从麦克风信号里把那部分减掉。视频会议软件不把对方声音传回去，用的就是它。

但在 macOS 上它有两个躲不开的代价，我们都实际踩过：

**1. 整台电脑的音量会被压低。**

这个单元是给 VoIP 用的，一旦初始化，macOS 就把系统里其他所有音频压低 ——
跟你在通话中一样。控制这个行为的属性（`kAUVoiceIOProperty_DuckNonVoiceAudio`）
**只有 iOS 有，而且已废弃，macOS 上开发者关不掉。**

症状是"不知道为什么我电脑所有声音都变小了"，而且根本想不到是听写工具干的。

**2. 它会把麦克风整个变哑。**

打开之后输入格式会从单声道变成多声道（常见是 5 声道）。`AVAudioConverter`
在声道数不匹配、又没给声道映射时**不报错** —— 它安静地输出全零。

于是：权限是好的、引擎在跑、tap 在正常回调，**每一个采样都是 0**。这跟
"你根本没说话"在代码里逐字节一样，一路伪装成了权限问题。

声道映射那条已经修了（`converter.channelMap` 只取第 0 路），而且加了自愈 ——
真录到全静音而回声消除又开着，就自动把它摘掉。但代价 1 修不了，所以默认关。

### 那外放怎么办：人声门限

顺带说一句：**就算没有上面那两个代价，回声消除也解决不了这件事。**

1. **它减的是信号，不是声音。** 系统知道自己往扬声器送了什么，就把那一路
   减掉。但声音从扬声器出来、在房间里弹一圈再回到麦克风，已经不是原来那一路
   信号了 —— 音量越大、离扬声器越近，残留越多。
2. **它不做人声分离。** 只要有人声漏进麦克风，模型听起来跟你说话一模一样，
   没有任何办法从「这是一句话」推出「这句话不是你说的」。

真正管用的是**人声门限**，而且它没有任何副作用。

```bash
./scripts/config.sh set voiceThreshold 0.05   # 默认 0.05，0 = 关掉
```

低于门限的声音直接写成静音，压根不送去转写。它靠的是距离差：你的嘴离麦克风
二三十厘米，视频的声音要绕一圈才回来，到麦克风时通常弱一个数量级。

门限该设多少取决于你的机器、麦克风位置、扬声器音量和房间，猜不出来，
所以菜单里有 **「校准人声门限…」**：

1. 第 1 步 4 秒，**别说话**，让视频照常放 → 量到「漏进来的有多响」
2. 第 2 步 4 秒，**正常说一句话** → 量到「你有多响」
3. 它取两者的几何平均给出建议值，一键写进配置

量完还会顺带回答一个更要紧的问题：这两者**分不分得开**。要是差距不到
1.6 倍，它会直说「分不开」而不是给一个看着很精确的数字 —— 那种情况下
调什么门限都是要么继续漏、要么开始吞字，该做的是戴耳机。

不想校准也可以手动一次调一档：

- 外放的视频还是会被转进来 → **调大**（0.08、0.12）
- 自己小声说话被吞掉了 → **调小**（0.03、0.02）

被门限整段挡掉时浮层会直说「声音都低于人声门限（最大 0.02，门限 0.05）」，
带着实测响度，照着调就行 —— 不会让你对着一个「没识别出内容」猜半天。

门限带 0.4 秒保持和一块的前瞻，所以不会把词头词尾削掉。

**真想完全隔绝，请戴耳机。** 声音根本不进麦克风，才是真的隔绝；上面两道闸都
只是在削弱，不是在归零。

## 「我明明开了麦克风权限，它却说没听到声音」

这个困惑是合理的，你没记错 —— 开关确实是开的，授权确实失效了。

这个 App 是 **ad-hoc 签名**的（`codesign --sign -`，没有开发者证书）。macOS 的
TCC 按代码签名记授权，而 ad-hoc 签名的哈希跟着二进制走：**每次重新编译，
哈希就换一个，那条授权记录就对不上了。**

恶心的地方在于它不会报错。系统设置里那个开关照常显示为开，麦克风也照常
"工作"，只是送来的样本**全是零** —— 跟"你没说话"在代码里长得一模一样。

自救：

```bash
./scripts/permissions.sh status   # 看签名跟上次授权时是不是同一个
./scripts/permissions.sh reset    # 清掉记录、重启 App，重新弹窗
```

App 菜单里也有一个「重新申请麦克风权限…」，做的是同一件事。

`install.sh` 现在会在签名变化时提前提醒你，不用等到听写失败才发现。

### 快捷键完全没反应时，先看 App 自报状态

```bash
./scripts/doctor.sh | head -30
```

「App 自报状态」那一栏是 App 自己写的，回答四个从终端看不到的问题：

- **App 还活着吗** —— 状态文件的刷新时间超过 30 秒就说明它没在跑
- **有没有辅助功能权限** —— `"accessibility": false` 就是快捷键没反应的直接原因
- **监听装上了吗** —— `hotkeyMonitorInstalled`
- **听的是哪个键** —— `hotkeyName`，确认不是配置被改过了

没有这份文件之前，这几件事只能靠猜。

### 快捷键突然完全没反应了，也是这个

全局快捷键监听（`NSEvent` 的全局监听器）**需要辅助功能权限** —— 不只是
"往输入框里插字"需要，"知道你按了哪个键"本身就需要。所以签名一变，辅助功能
授权失效，按 Option 键就是彻底没反应：没有浮层、没有报错、什么都没有。因为
按键事件根本就没送到这个 App。

`permissions.sh reset` 两个都会重置。麦克风会自动弹窗，辅助功能要手动加回去
（系统设置 › 隐私与安全性 › 辅助功能 → `+` → MixDictate）。

### 固定签名身份：一劳永逸

```bash
./scripts/signing.sh setup        # 建一个自签名的代码签名证书
./install.sh                      # 重新编译，这次用它签名
./scripts/permissions.sh reset    # 重新授权一次（最后一次）
```

之后 TCC 认的是**证书**而不是二进制哈希，重编译多少次都还是"同一个 App"，
授权一直留着。

**关于证书要花不花钱，说清楚：**

| 方式 | 要钱吗 | 能干什么 |
|---|---|---|
| 自签名证书（上面这个） | 不要，也不用 Apple ID | 只在你自己这台机器上有效，够解决权限问题 |
| 免费 Apple ID 的 Apple Development 证书 | 不要钱，要注册 Apple ID | 同上，但要装 Xcode、走一遍登录流程 |
| Developer ID（付费账号 $99/年） | 要 | **给别人用**才需要 —— 别人的 Mac 上 Gatekeeper 要验签和公证 |

所以：**自己用，自签名就够了，一分钱不花，连 Apple ID 都不用注册。**
只有到了"想发给别人装"那一步，才必须买付费账号。

`signing.sh setup` 如果失败了，图形界面那条路更稳：钥匙串访问 › 菜单栏「钥匙串
访问」› 证书助理 › 创建证书 → 名称填 `MixDictate Dev`、身份类型选「自签名根证书」、
证书类型选「代码签名」→ 建好后双击它，把「信任」里的「代码签名」设为「始终信任」。
建完再跑 `./install.sh` 就会自动用上。

## 停顿的时候它自己加了个句号

模型判断一句话说完没有，最主要的依据就是**停顿有多长**。麻烦在于「我在想
下一句怎么说」和「这句我说完了」在音频里是同一件事 —— 一段安静。从声音里
根本分不开，之前试过按停顿时长猜（停 2 秒以上算说完），猜错的比猜对的多。

所以现在不猜，直接把线索削掉：**送给模型之前，把过长的静音压短**。1.5 秒的
思考停顿压成 0.35 秒，模型看到的就只是个正常的字间空隙，没理由断句了。

```bash
./scripts/config.sh set maxPauseSeconds 0.2    # 更不容易乱加句号
./scripts/config.sh set maxPauseSeconds 0.8    # 更尊重你的停顿
./scripts/config.sh set maxPauseSeconds 0      # 不压，交给模型自己判断
```

顺带一个好处：音频变短了，推理也更快。

这依赖人声门限 —— 门限把停顿写成真正的静音，压缩才认得出来哪里是停顿。
两个功能是一套的。

### 第二道：从文字那侧补救

压短停顿是从**声音**那一侧削线索，但模型还会看语调，总有漏网的。所以再补
一道文字侧的：**句号后面跟着什么，本身就是最好的线索。**

后面跟着「然后」「但是」「所以」「而且」「就是」这类接续词，说明这句根本
没说完 —— 把句号降级成逗号。声音里分不开的东西，文字里常常分得开。

```bash
./scripts/config.sh set mergePausePeriods false   # 不想要的话关掉
```

**它只降级标点，绝不删字。** 这两种错误的代价完全不对等：删掉的内容你根本
不知道它曾经存在过，多余的标点你一眼就能看见并改掉。同理它也只在有明确
词汇证据时才动手 —— 「的」「了」「过」看着也像不能起头的字，但「的确」
「了不起」「过去」都能正常开句，所以宁可漏掉也不误伤。

这条路子不是我拍脑袋想的：标点恢复的研究里，纯文本模型往往比带韵律的多模态
模型更可靠，原因正是**口述场景下说话人的停顿本来就不对应标点**（朗读才对应）。
用右侧上下文回头改已经打出来的标点，也是流式标点恢复的标准做法 —— 边界处
的判断缺右文，等右文到了再改。

**两道加起来仍是削弱，不是保证。** 真要一个句号都不自动加，目前只能自己删。

## 一句话拖很长，一个逗号都没有

这是上面那件事的**反面**，成因却是同一个。模型下标点主要靠停顿，而说得顺的
时候分句处根本不停 —— 没有停顿，就没有逗号。我们又主动把长静音压短了
（`maxPauseSeconds`），等于把这条线索削得更薄。

所以同样从文字侧补：**接续词就是分句的位置，这一点不用听也知道。**

> 那个热词自动学习可以开始了然后逗号识别有点怪
> → 那个热词自动学习可以开始了**，**然后逗号识别有点怪

```bash
./scripts/config.sh set splitClauses false   # 不想要的话关掉
```

只在前面已经攒了 8 个字以上没断过时才补 —— 否则句首的「然后」也会被塞个
逗号，反而更碎。**只加逗号，不动任何字**，有测试钉住。

## 热词：从你说过的话里找

```
菜单栏 › 从听写记录里找热词…
```

它扫本机的转写记录，把**反复出现两次以上的英文词**挑出来（技术名词、产品名、
缩写 —— 热词表最能帮上忙的正是这些），列成一个带勾选框的窗口。

三条边界是刻意的：

**只读本机的转写记录。** 不读输入框、不碰别的 App、不联网。最初想的是读当前
输入框的内容来学词，那样候选更准，但它要去读你正在写的东西 —— 邮件、密码框
旁边的字段、别人发来的消息。改成只看转写记录之后，读到的全是你自己对着这个
App 说过的话。

**只读「原始」那几行**，也就是模型自己吐出来的。读「输出」等于把后处理改过的
结果又喂回去，让规则自我强化。

**没有任何自动入表的路径。** 词表是拿去偏置解码器的 —— 一个听错的词进了表，
会让模型把这个错误听得**更稳定**，那比不加还糟。所以勾选和「加入」必须是人做
的动作。同理它只挖英文词：中文很难从统计上分清「你常用的术语」和「听错的字」。

### 从你的修改里学（默认关）

```bash
./scripts/config.sh set learnCorrections true
```

打开后，听写完几秒钟它会回头看一眼：**我们写进去的那一段，你改了什么。**
同一个改动出现 **3 次**就写成一条别名规则，以后自动改对，并弹一下告诉你学了什么。

为什么这个可以自动、上面那个必须人工确认：**你改过的字是硬证据。** 它说明这个
词确实一直被听错。而候选词只是"你说得多" —— 说得多不代表听错了。两者的证据
强度不一样，待遇也不该一样。

3 次这个门槛也是这个意思：一次是手滑，两次可能是巧合，三次就是"它每次都听错
这个词"。

**这是唯一会碰输入框的功能，所以口子开得很小：**

- **只按范围读我们自己写的那一段**（`kAXStringForRange`）—— 向系统要的就只有
  这一段，承诺落在接口这一层，而不是"读回全文之后我们自觉不看别的"
- **控件不支持按范围读就放弃这次学习**，绝不退回去读全文
- **只认小改动**：改一两个词是"它听错了"，整段重写是"我改主意了"，后者不该被
  学成听写错误
- 学到的只存本机（`corrections.json`），不联网

不想让它碰输入框就一直关着 —— 上面那个「从听写记录里找热词…」不需要这个开关。

## 第一次特别慢，用几次就快了

这是 MLX 的 **Metal 计算核在首次推理时才编译**，而且核是**按张量形状**编的
—— 输入音频多长直接决定形状。所以每碰到一个没见过的长度就要现编一批，
编过的越多、撞上缓存的概率越大，主观感受就是「用得越多越快」。

现在服务启动时会用 **0.8 / 2.5 / 6 秒三档**各跑一遍推理，把常见长度的核在
你按第一次快捷键之前就编好。按下说话键时还会再补一次轻量重热（闲置久了
资源会被换出去）。

启动时因此会多花几秒 —— 但那几秒花在你没在等的时候，比落在你第一句话上强。


```bash
./scripts/config.sh set rawOutput true
```

打开后所有文字加工全部失效，你拿到的就是模型原文。再说同一句话对比一下：

- **原文就怪** → 模型听错了。解法是加热词，或者换 1.7B 模型
- **原文对、加工后怪** → 是后处理的 bug。把两行贴出来，能直接定位

不打开也能看 —— 转写记录里本来就同时记着两行：

```bash
open ~/Library/Application\ Support/MixDictate/logs/transcripts.log
```

## 测试准确率

每次转写都会记到 `~/Library/Application Support/MixDictate/logs/transcripts.log`，
**原始输出和处理后结果并排**：

```
2026-08-18 03:12:44  [0.83s]
  原始: 把它部署到kubernetes上面,用github actions跑CI
  输出: 把它部署到 Kubernetes 上面，用 GitHub actions 跑 CI
```

菜单里点「查看转写记录…」直接打开。

两个都记是有意的：只看最终结果分不清**是模型听错了，还是后处理改坏了**。
这两种问题的解法完全不同 —— 前者加热词，后者要改代码。

### 建议的测试流程

1. 找个文本编辑器，连续说 20-30 句你**平时真会说的话**（带上你常用的术语、人名、项目名）
2. 打开转写记录，逐条看
3. 分类：
   - **原始就错**（比如 `kubernetes` 听成 `库伯内特斯`）→ 加进热词表，或加别名 `库伯内特斯 => Kubernetes`
   - **原始对但输出错**（后处理把对的改坏了）→ 把这条贴出来，是代码 bug
4. 改完热词表保存，重测那几句

热词表的效果通常比换更大的模型明显 —— 先把热词调好再考虑上 1.7B。

### 目前没有的

- **情绪 / 语气识别**（"这句话是疑问还是感叹"之外的情感标签）—— Qwen3-ASR 不输出
  情绪标签。需要的话得换 SenseVoice，那是另一个模型，另说。
- 标点本身是有的：模型自己会输出，我们再做全角化和规则修正。

## 排错

**先跑诊断**，一条命令收集所有信息：

```bash
./scripts/doctor.sh
```

**转写出不来东西时**，跑自检 —— 它拿最近一次录音直接走完整条链路，
把每一步的中间结果都打出来：

```bash
./scripts/selftest.sh
```

它会分别用「带热词」和「不带热词」各转一次，再逐段展示后处理的结果，
最后直接给出结论：是模型没输出、热词偏置把解码带跑偏了、还是后处理
把内容洗没了。这三种问题的解法完全不同。

---

**按住说话键完全没反应（浮层都不出现）** —— 几乎一定是缺辅助功能权限。

macOS 的全局按键监听**本身就需要这个权限**，没有它 App 收不到任何按键 ——
所以表现不是"转写失败"，而是整个流程压根不启动。

去 系统设置 › 隐私与安全性 › 辅助功能 打开 MixDictate。**不用重启 App**，
它每 2 秒自己检查一次，权限一生效会弹窗告诉你。

**列表里找不到 MixDictate，或者开关打开了也不管用？**

权限是按代码签名记的，而每次 `./install.sh` 都会重新 ad-hoc 签名 ——
重装过几次之后，旧的权限记录会跟新签名对不上，表现就是列表里没有它，
或者有但勾了没用。清空重来：

```bash
tccutil reset Accessibility dev.mixdictate.app
pkill -x MixDictate
open -a MixDictate
```

重启后系统会重新弹授权对话框。也可以用菜单里的「重新申请辅助功能权限」。


**菜单栏图标一直是沙漏** —— 在下模型。菜单里「查看服务日志…」能看到进度。

**图标是橙色三角** —— 点开菜单，第一行就是错误原因。

**浮层显示「没识别出内容」** —— 音频进来了但模型没输出。菜单里点
「播放最近一次录音…」听一下：

- 能听清自己说话 → 录音链路没问题，问题在模型或热词偏置。服务日志里会写明
  是不是热词造成的（服务端在结果为空时会自动去掉热词重试一次）。
- 听不清 / 是静音 → 问题在录音链路，检查麦克风权限和系统的输入设备选择。

设成 `MIXDICTATE_SAVE_AUDIO=0` 可以关掉录音留存。

**能看到浮层出字，但文字没插进输入框** —— 辅助功能权限没给。这种情况
App 会弹窗提示，并且**文字已经在剪贴板里，可以直接 Cmd+V**。
设置界面顶部也会显示权限状态，点「去授权」直接跳到对应的设置页。

重装 App 后权限会失效（macOS 按应用签名记权限），要在系统设置里把旧条目
删掉重新添加。

**说话没反应** —— 确认按的是右 Option 不是左 Option。改键见配置一节。
如果听到"叮"一声，说明服务还没就绪。

**菜单栏图标找不到** —— 图标是个**麦克风**符号，在右侧时钟那一排。
按住 `Cmd` 拖动菜单栏图标可以重新排序，把它拖到时钟旁边就不容易被挤掉。

不想折腾的话，菜单里的功能都有对应的命令：

```bash
open ~/Library/Application\ Support/MixDictate/logs/last_request.wav  # 听最近一次录音
open ~/Library/Application\ Support/MixDictate/logs/transcripts.log   # 看转写记录
open ~/Library/Application\ Support/MixDictate/logs/server.log        # 看服务日志
open -e ~/Library/Application\ Support/MixDictate/hotwords.txt        # 改热词表
```

`./scripts/doctor.sh` 的结尾也会把这些命令打出来。

**菜单栏里根本看不到图标** —— 刘海屏图标太多会被挤到刘海后面（退几个别的
菜单栏 App 试试，或用 Bartender / Ice 管理）；也可能 App 压根没起来，
在「应用程序」里双击看有没有报错。

## 开发

```bash
make dev-setup         # 在 server/.venv 建独立的开发环境
make test              # 全部测试，不需要模型，任何平台都能跑
make dev-server        # 前台跑服务，看实时日志
make dev-server-mock   # 不加载模型空跑，验证链路
make app               # 只重新编译 App
```

开发环境（`server/.venv`）和 App 用的环境
（`~/Library/Application Support/MixDictate/venv`）是分开的，互不干扰。

测试分三层：`test_postprocess.py` 测纯函数，`test_paths.py` 测路径解析和词表播种，
`test_server.py` 用 mock 后端走完整 HTTP 链路。都不需要 mlx，所以 CI 在 Linux 上就能跑。

CI（`.github/workflows/ci.yml`）跑四个 job：Python 测试（3.10 / 3.12）、
Apple Silicon runner 上的 Swift 编译 + bundle 校验、shellcheck。

## 状态

**早期原型。** Python 侧 97 个测试覆盖，Swift 侧由 CI 在 Apple Silicon runner
上编译验证。但**完整的录音 → 转写 → 注入流程还没在真机上端到端跑过** ——
权限授予、真实模型推理、剪贴板注入在各 App 里的行为，这几段需要人工验证。
